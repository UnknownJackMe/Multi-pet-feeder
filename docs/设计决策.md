# 设计决策

本文记录 V1 的关键架构决策，以及外部开源项目如何影响本项目设计。

## 许可证规则

本仓库使用 Apache-2.0 许可证。

部分参考项目使用 GPL 系列许可证，因此：

- 可以参考其架构、状态机组织、硬件经验和故障模式；
- 不直接复制 GPL 项目的源文件或大段实现；
- 接口和算法独立重写；
- 对重要设计来源进行记录；
- 引入任何第三方库前，单独确认其许可证兼容性。

## D-001：ESP32-S3 是权威本地主控

**决策：** 核心喂食与门禁逻辑运行在 ESP32-S3 上，采用 ESP-IDF / C++。

**原因：**

- 本地行为确定；
- 不依赖 Wi-Fi、MQTT、NUC 或云服务；
- GPIO 和外设资源足够；
- 原生支持 FreeRTOS 与 ESP Event Loop。

Camera / NUC 在 V1 中仅提供辅助信息。

## D-002：事件驱动组件 + 显式安全协调器

**决策：** 驱动层只上报观察结果，业务域负责决策。

```text
传感器 / 驱动组件
        ↓ events
身份 / 在场融合 / 门反馈
        ↓
Access Control FSM
        ↓ commands
门控 / 出粮控制器
```

事件总线不能掩盖安全责任边界：只有 Access Control FSM 可以授权打开内门。

## D-003：采用双门认证缓冲舱

**决策：** 食物访问通过“外门 + 缓冲舱 + 内门”的气闸式结构实现。

**硬约束：** 两扇门不能同时物理开启。

**原因：** 单纯 RFID 开盖无法解决尾随；物理隔离能够创造一个二次认证窗口。

## D-004：授权采用 Fail-Closed

**决策：** 任何关键身份 / 占用证据不一致，都禁止打开内门。

V1 必须同时满足：

- 已授权 RFID 身份；
- 外门已确认关闭；
- 内门当前已确认关闭；
- 外门 / 内门光幕均清空；
- 缓冲舱只存在一只合理目标；
- 缓冲舱重量符合授权宠物；
- 所有关键传感器健康。

不采用多数投票。

## D-005：门状态必须测量，不能假设

**决策：** 舵机 / 电机命令不代表真实门状态，必须由限位开关确认。

原因：执行器可能堵转、打滑或断电丢位置。

## D-006：上电必须归零和自检

启动顺序：

1. 初始化驱动；
2. 检查关键传感器；
3. 读取限位状态；
4. 将两扇门归到已知安全位置；
5. 在安全条件下校验 / 去皮称重；
6. 恢复喂食账本；
7. 通过全部检查后进入 `IDLE`。

禁止从持久化的“临时门命令状态”直接恢复会话。

## D-007：RFID 实现必须抽象

业务逻辑只消费标准化的 `PetTagObserved`，不直接依赖 RC522、WL-134、RDM6300 等具体模块。

V1 优先选择适合宠物通道几何的 125 / 134.2 kHz 方案，并通过真宠物运动姿态实测读距。

## D-008：RFID 供电与电机噪声隔离

电机 / 舵机电源与 RFID / 逻辑电源尽量分开，并进行本地滤波和合理的星形供电。

原因：参考项目 MeowPass 明确记录了劣质或高噪声供电显著降低 RFID 读取距离。

## D-009：身份与在场数量分离

```text
RFID -> 谁可能在这里
ToF / 光幕 / 地板称重 -> 有几只、在哪里、通道是否清空
```

读到合法 RFID 绝不等价于 `occupancy == 1`。

## D-010：Camera 不进入 V1 安全闭环

Camera / YOLO 可以：

- 录像；
- 数宠物；
- 辅助调试；
- 为未来 ReID 提供数据。

但摄像头故障不能影响基础喂食和机械安全。

## D-011：三粮仓 + 一个共享称重碗

V1 采用三路独立粮仓和电机，共享一个称重食盆。

这不保证处方粮级零串粮。如果未来要求严格物理隔离，则 V2 改为独立碗 / 独立落粮路径或自动换碗机构。

## D-012：出粮必须做重量闭环

流程：

1. 食盆稳定 / 去皮；
2. 快速粗出粮；
3. 接近目标后减速 / 脉冲；
4. 达到容差后停止；
5. 电机动作但重量不增加 → 卡粮判断；
6. 反转后有限次数重试；
7. 反复失败 → 锁存故障。

禁止仅按“电机运行多少秒”控制份量。

## D-013：持久化喂食账本防止重复出粮

至少保存：

- meal/session ID；
- 宠物 ID；
- 粮仓通道；
- 目标重量；
- 已出粮重量；
- 会话状态；
- 完成时间。

重启后先对账再继续，不能直接重新出一整份。

## D-014：安全逻辑必须能在 PC 上独立测试

Access Control 策略实现为硬件无关的纯状态机：普通数据输入、动作命令输出。

ESP-IDF 驱动只是适配层。

必须能确定性测试：

- 正常授权通行；
- 错误宠物；
- 双宠尾随；
- 门口遮挡；
- 限位矛盾；
- 传感器失效；
- 断电 / 重启；
- 执行器超时。
