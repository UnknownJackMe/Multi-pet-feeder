# 接口设计

V1 将硬件驱动与业务决策严格分离：驱动只上报观测值，业务域组件决定允许执行什么动作。

## 1. 核心类型

```cpp
enum class PetId {
    Unknown,
    Sushi,
    Coconut,
    Blueberry,
};

enum class DoorId {
    Outer,
    Inner,
};

enum class DoorPhysicalState {
    Unknown,
    Closed,
    Open,
    Moving,
    Fault,
};

enum class HopperId {
    Sushi,
    Coconut,
    Blueberry,
};
```

持久化存储中应使用稳定的数值 / 字符串 ID，这些枚举仅用于 V1 代码表达。

## 2. RFID Reader

### 责任

将不同读卡器的原始帧统一转换成标准标签观测。

```cpp
struct PetTagObserved {
    uint64_t tag_id;
    int64_t timestamp_ms;
    int signal_quality; // 无法提供时填 -1
};
```

RFID 驱动不负责判断该标签是否有权限。

## 3. 宠物身份服务

### 责任

将 Tag ID 映射到宠物配置和当前喂食权限。

```cpp
struct PetProfile {
    PetId id;
    uint64_t tag_id;
    float min_chamber_mass_kg;
    float max_chamber_mass_kg;
    HopperId hopper;
};
```

输出：

```cpp
struct PetIdentityResult {
    bool known;
    bool currently_allowed;
    PetProfile profile;
};
```

## 4. ToF 占用检测

### 责任

提供缓冲舱占用证据，不直接做门禁授权。

```cpp
struct ToFOccupancySample {
    bool healthy;
    int occupied_zone_count;
    int cluster_count;
    float nearest_range_m;
    int64_t timestamp_ms;
};
```

VL53L5CX 的第一版算法可以保持简单：

- 剔除无效 zone；
- 与空舱基线做前景差分；
- 统计占用区域；
- 对占用区做连通域 / 聚类；
- 输出 cluster 数量和健康状态。

## 5. 门槛光幕

```cpp
struct BeamState {
    bool healthy;
    bool blocked;
    int64_t stable_since_ms;
};
```

必须存在：

- `outer_threshold_beam`
- `inner_threshold_beam`

## 6. 缓冲舱称重

```cpp
struct ScaleSample {
    bool healthy;
    float mass_kg;
    bool stable;
    int64_t timestamp_ms;
};
```

只用于占用合理性，不追求兽医级体重精度。

## 7. 食盆称重

```cpp
struct BowlMassSample {
    bool healthy;
    float mass_g;
    bool stable;
    int64_t timestamp_ms;
};
```

## 8. 门控制器

### 命令

```cpp
enum class DoorCommand {
    Open,
    Close,
    Stop,
    HomeClosed,
};
```

### 反馈

```cpp
struct DoorFeedback {
    DoorId door;
    DoorPhysicalState state;
    bool open_limit;
    bool closed_limit;
    bool actuator_fault;
    int64_t timestamp_ms;
};
```

规则：

- 动作完成必须由物理反馈确认；
- `open_limit && closed_limit` 属于矛盾故障；
- 门移动必须有超时；
- 防夹由门本地安全层和 Access FSM 共同约束；
- 超时不能被静默转换成 `Open` 或 `Closed`。

## 9. Presence Fusion

输入：

- 当前身份候选；
- ToF 占用；
- 缓冲舱重量；
- 两侧光幕；
- 传感器健康度。

输出：

```cpp
enum class OccupancyVerdict {
    Empty,
    ExactlyOnePlausiblePet,
    MultipleOrTailgatingSuspected,
    Ambiguous,
    SensorFault,
};

struct PresenceVerdict {
    OccupancyVerdict verdict;
    bool mass_matches_authorized_pet;
    bool outer_threshold_clear;
    bool inner_threshold_clear;
};
```

Presence Fusion 只提供证据，真正决定能否开内门的是 Access Control。

## 10. Access Control FSM

```cpp
struct AccessInputs {
    PetIdentityResult identity;
    PresenceVerdict presence;
    DoorFeedback outer_door;
    DoorFeedback inner_door;
    bool feeding_session_available;
    int64_t now_ms;
};
```

动作输出：

```cpp
struct AccessActions {
    bool open_outer = false;
    bool close_outer = false;
    bool open_inner = false;
    bool close_inner = false;
    bool invalidate_authorization = false;
    bool enter_fault = false;
};
```

状态机必须确定性：相同状态 + 相同输入快照应得到相同转移和动作。

## 11. 出粮控制器

```cpp
struct DispenseRequest {
    HopperId hopper;
    float target_mass_g;
    float tolerance_g;
    uint32_t max_jam_retries;
};

enum class DispenseResult {
    Completed,
    BowlScaleFault,
    Jammed,
    Timeout,
    Cancelled,
};
```

出粮控制器同时使用电机反馈和食盆重量闭环。

## 12. Scheduler

Scheduler 输出的是“喂食许可窗口”，而不是直接控制电机。

```cpp
struct MealWindow {
    uint64_t meal_id;
    PetId pet;
    float target_mass_g;
    int64_t start_epoch_s;
    int64_t end_epoch_s;
};
```

只有正确宠物完成身份认证后，喂食会话才消费这个窗口。

## 13. 喂食账本

```cpp
struct FeedingLedgerEntry {
    uint64_t meal_id;
    PetId pet;
    HopperId hopper;
    float target_mass_g;
    float dispensed_mass_g;
    bool completed;
};
```

写入必须具备足够的幂等性，避免重启后同一餐再次完整出粮。

## 14. Fault Manager

初始故障码：

```text
DOOR_CONTRADICTORY_LIMITS
DOOR_MOVE_TIMEOUT
DOOR_OBSTRUCTION
RFID_UNHEALTHY
TOF_UNHEALTHY
CHAMBER_SCALE_UNHEALTHY
BOWL_SCALE_UNHEALTHY
TAILGATING_SUSPECTED
DISPENSER_JAM
POWER_RECOVERY_REQUIRED
```

每个故障必须定义：

- 严重级别；
- 是否允许继续喂食 / 通行；
- 本地恢复动作；
- 遥测字段。

## 15. Event Bus 使用规则

推荐事件族：

```text
sensor.rfid
sensor.tof
sensor.beam
sensor.scale
actuator.door
actuator.hopper
domain.identity
domain.presence
domain.access
domain.feeding
domain.fault
system.boot
system.network
```

安全关键转移必须明确存在于 Access Control Core 中，并由确定性测试覆盖。
